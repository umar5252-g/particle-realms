# 🌸 Particle Realms

A collection of interactive 3D particle scenes built entirely in the browser using **WebGL** and **Three.js**. No build tools, no frameworks — just single HTML files you can open and explore.

## 🛠️ Technologies Used

### Core: Three.js

**Three.js** is a JavaScript library that makes WebGL (the browser's 3D engine) easy to use. Without Three.js you'd write hundreds of lines of raw WebGL code just to draw a single triangle. Three.js gives you a simple scene → camera → renderer pattern.

```
Scene (your 3D world)
 ├── Camera (your eyes — what you see)
 ├── Lights (how things are lit)
 ├── Meshes (3D objects = Geometry + Material)
 └── Particles (thousands of points)

Renderer → draws the Scene from the Camera's view onto a <canvas>
```

**Version used:** `r128` (via CDN script tags) and `r164` (via ES module import maps)

**CDN Sources:**
- `cdnjs.cloudflare.com/ajax/libs/three.js/r128/three.min.js`
- `cdn.jsdelivr.net/npm/three@0.164.1/build/three.module.js`

### What Each Three.js Feature Does

#### Scene Setup

| Code | What It Does |
|---|---|
| `new THREE.Scene()` | Creates the 3D world — everything you see is added to this |
| `new THREE.PerspectiveCamera(fov, aspect, near, far)` | Your virtual eye. `fov` = field of view angle, `aspect` = width/height ratio |
| `new THREE.WebGLRenderer({ antialias: true })` | Takes the scene + camera and draws it onto an HTML `<canvas>` using your GPU |
| `renderer.setPixelRatio(Math.min(devicePixelRatio, 2))` | Makes it sharp on retina screens but caps at 2× to save performance |
| `scene.fog = new THREE.FogExp2(color, density)` | Fades distant objects into a color — creates depth & atmosphere |
| `scene.background = new THREE.Color(hex)` | Sets the background color of the 3D world |

#### 3D Objects (Geometries + Materials)

| Code | What It Does |
|---|---|
| `new THREE.CylinderGeometry(...)` | Creates a tube/cylinder shape (used for tree trunks & branches) |
| `new THREE.SphereGeometry(...)` | Creates a sphere shape (used for foliage clusters) |
| `new THREE.PlaneGeometry(w, h, segX, segY)` | Creates a flat surface divided into a grid (used for the ocean) |
| `new THREE.ConeGeometry(...)` | Creates a cone (used for the floating island rock) |
| `new THREE.OctahedronGeometry(...)` | Creates a diamond-like shape (used for crystals) |
| `new THREE.MeshStandardMaterial({...})` | A realistic material that reacts to light (color, roughness, metalness) |
| `new THREE.MeshBasicMaterial({...})` | A flat material that ignores light — always the same color |
| `new THREE.Mesh(geometry, material)` | Combines a shape + appearance into a visible 3D object |

#### Particle Systems

This is the heart of these projects. Instead of complex 3D meshes, you create **thousands of points** (dots) and move them with math.

| Code | What It Does |
|---|---|
| `new THREE.BufferGeometry()` | An empty container for raw vertex data (positions, colors, sizes) |
| `new Float32Array(count * 3)` | Creates a high-performance typed array — every 3 values = X, Y, Z position |
| `geo.setAttribute('position', new THREE.BufferAttribute(array, 3))` | Attaches position data to the geometry (3 values per vertex) |
| `geo.setAttribute('color', new THREE.BufferAttribute(array, 3))` | Attaches per-point colors (R, G, B for each point) |
| `new THREE.PointsMaterial({...})` | Simple material for point clouds — controls size, color, transparency |
| `new THREE.Points(geometry, material)` | Renders the geometry as a cloud of dots instead of a solid shape |
| `positions.needsUpdate = true` | Tells Three.js "I changed the array in JS, re-upload it to GPU memory" |
| `THREE.AdditiveBlending` | When points overlap, their colors ADD together — creates glowing effects |

#### Lights

| Code | What It Does |
|---|---|
| `new THREE.AmbientLight(color, intensity)` | Lights everything equally from all directions — base illumination |
| `new THREE.DirectionalLight(color, intensity)` | Sunlight/moonlight — parallel rays from one direction |
| `new THREE.PointLight(color, intensity, distance)` | A lightbulb — radiates outward from a point, fades over distance |

#### Controls

| Code | What It Does |
|---|---|
| `new OrbitControls(camera, canvas)` | Lets you drag to rotate, scroll to zoom, right-drag to pan |
| `controls.enableDamping = true` | Makes the camera glide smoothly instead of stopping instantly |
| `controls.maxPolarAngle` | Limits how far up/down you can rotate (prevents looking under the ground) |
| `controls.minDistance / maxDistance` | Limits zoom range |

### Post-Processing: UnrealBloomPass

Post-processing = applying image effects AFTER the 3D scene is rendered, like Instagram filters on each frame.

| Code | What It Does |
|---|---|
| `new EffectComposer(renderer)` | A pipeline that chains multiple render passes together |
| `new RenderPass(scene, camera)` | The first pass — renders the normal 3D scene |
| `new UnrealBloomPass(resolution, strength, radius, threshold)` | **The glow effect.** Takes bright pixels and bleeds their light outward |
| `composer.render()` | Runs all passes and outputs the final glowing image to screen |

**How bloom works:**
1. Render the scene normally
2. Find pixels brighter than `threshold`
3. Blur those bright pixels outward by `radius`
4. Add the blurred brightness back with `strength` intensity
5. Result: bright things glow ✨

**Required dependencies (loaded as separate scripts):**
- `EffectComposer.js` — the pass chain manager
- `RenderPass.js` — renders the base scene
- `ShaderPass.js` — runs a shader on the full-screen image
- `CopyShader.js` — copies one buffer to another
- `LuminosityHighPassShader.js` — finds the bright pixels
- `UnrealBloomPass.js` — the actual bloom effect

### Custom Shaders (GLSL)

Some scenes use `THREE.ShaderMaterial` to write custom GPU programs. These are written in **GLSL** (OpenGL Shading Language).

| Shader Type | What It Does |
|---|---|
| **Vertex Shader** | Runs once PER VERTEX — controls where each point appears on screen. Used for ocean waves, particle sizes |
| **Fragment Shader** | Runs once PER PIXEL — controls what color each pixel is. Used for gradients, glow, transparency |

**Example — Ocean waves ([blossom-ocean.html](file:///e:/3d-particles/blossom-ocean.html)):**
```glsl
// Vertex shader: displaces a flat plane into waves
float wave1 = sin(pos.x * 0.3 + uTime * 0.8) * cos(pos.y * 0.25 + uTime * 0.6);
pos.z = wave1;  // move the vertex up/down based on a sine wave
```

**Example — Fresnel glow on foliage ([blossom-ocean.html](file:///e:/3d-particles/blossom-ocean.html)):**
```glsl
// Fragment shader: edges glow brighter than the center
float fresnel = pow(1.0 - abs(dot(normalize(vNormal), normalize(-vPos))), 2.5);
```

**Key GLSL concepts used:**
| Concept | Meaning |
|---|---|
| `uniform` | A value sent from JavaScript to the shader (e.g., time, audio level) |
| `attribute` | Per-vertex data from the geometry (e.g., position, size, color) |
| `varying` | A value passed from vertex shader → fragment shader (interpolated across the surface) |
| `sin() / cos()` | Trigonometry — creates waves, oscillations, circles |
| `smoothstep()` | Smooth transition between two values — soft edges instead of hard cutoffs |
| `mix()` | Blend between two colors/values — like lerp/interpolation |
| `gl_PointSize` | How big each point particle appears on screen |
| `gl_PointCoord` | UV coordinate within a single point sprite (for making round dots) |
| `gl_FragColor` | The final output color of a pixel |

### Web Audio API (Microphone Input)

Used in [blossom-ocean.html](file:///e:/3d-particles/blossom-ocean.html) and [spirit-dragon.html](file:///e:/3d-particles/spirit-dragon.html) to make visuals react to sound.

| Code | What It Does |
|---|---|
| `new AudioContext()` | Creates the audio processing engine |
| `navigator.mediaDevices.getUserMedia({ audio: true })` | Requests microphone permission and starts capturing |
| `audioCtx.createAnalyser()` | Creates a node that can analyze frequency data from the audio stream |
| `analyser.fftSize = 256` | How many frequency samples to take (more = finer detail, slower) |
| `analyser.getByteFrequencyData(array)` | Fills an array with the current volume at each frequency (0–255) |

**Flow:**
```
Microphone → MediaStream → AnalyserNode → getByteFrequencyData() → audioLevel (0.0 to 1.0)
                                                                         ↓
                                                               Drives: wave height, glow intensity,
                                                                       particle speed, crystal pulse
```

| `renderer.toneMapping = THREE.ACESFilmicToneMapping` | Hollywood-grade color compression — richer darks, controlled highlights |

## 🔁 The Animation Loop Pattern

Every scene follows the same pattern:

```javascript
function animate() {
    requestAnimationFrame(animate);  // 1. Schedule the next frame (~60fps)
    
    const time = clock.getElapsedTime();  // 2. Get current time in seconds
    
    // 3. Update positions, rotations, uniforms
    particles.position.y += velocity;
    material.uniforms.uTime.value = time;
    
    // 4. Update controls (smooth camera damping)
    controls.update();
    
    // 5. Render the frame
    composer.render();  // (or renderer.render(scene, camera) without bloom)
}
animate();  // Start the loop
```

## 🧮 Key Math Concepts

| Math | Where It's Used | What It Does |
|---|---|---|
| `Math.sin(time)` / `Math.cos(time)` | Waves, orbits, pulsing | Creates smooth back-and-forth oscillation |
| `Math.random()` | Particle initialization | Gives each particle a unique position, speed, phase |
| `(Math.random() - 0.5) * range` | Spreading particles | Centers randomness around 0 (goes both negative and positive) |
| `smoothstep(edge0, edge1, x)` | Shaders | Smooth transition between 0 and 1 — no harsh edges |
| `Lissajous curves` | Dragon path | `sin(t) × A, sin(2t) × B` creates figure-8 / infinity paths |
| `Fresnel effect` | Foliage glow | Edges facing away from camera glow brighter — creates a rim light |
| `lerp / mix` | Color blending | Smoothly blends between two values: `a + (b - a) * t` |

## 🏗️ How to Build Your Own Scene (Step-by-Step Guide)

Want to create a custom 3D scene from scratch? Here is the exact boilerplate template and workflow to use:

### Step 1: Create a single `index.html` template

```html
<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <title>My 3D Particle Scene</title>
  <style>
    * { margin: 0; padding: 0; box-sizing: border-box; }
    body { overflow: hidden; background-color: #000; font-family: sans-serif; }
    canvas { display: block; width: 100vw; height: 100vh; }
  </style>
</head>
<body>

  <!-- Three.js + Bloom CDNs -->
  <script src="https://cdnjs.cloudflare.com/ajax/libs/three.js/r128/three.min.js"></script>
  <script src="https://cdn.jsdelivr.net/npm/three@0.128.0/examples/js/controls/OrbitControls.js"></script>
  <script src="https://cdn.jsdelivr.net/npm/three@0.128.0/examples/js/postprocessing/EffectComposer.js"></script>
  <script src="https://cdn.jsdelivr.net/npm/three@0.128.0/examples/js/postprocessing/RenderPass.js"></script>
  <script src="https://cdn.jsdelivr.net/npm/three@0.128.0/examples/js/postprocessing/ShaderPass.js"></script>
  <script src="https://cdn.jsdelivr.net/npm/three@0.128.0/examples/js/shaders/CopyShader.js"></script>
  <script src="https://cdn.jsdelivr.net/npm/three@0.128.0/examples/js/shaders/LuminosityHighPassShader.js"></script>
  <script src="https://cdn.jsdelivr.net/npm/three@0.128.0/examples/js/postprocessing/UnrealBloomPass.js"></script>

  <script>
    // 1. Scene, Camera, Renderer
    const scene = new THREE.Scene();
    scene.fog = new THREE.FogExp2(0x050010, 0.02);

    const camera = new THREE.PerspectiveCamera(60, window.innerWidth / window.innerHeight, 0.1, 1000);
    camera.position.set(0, 5, 20);

    const renderer = new THREE.WebGLRenderer({ antialias: true });
    renderer.setSize(window.innerWidth, window.innerHeight);
    renderer.setPixelRatio(Math.min(window.devicePixelRatio, 2));
    document.body.appendChild(renderer.domElement);

    const controls = new THREE.OrbitControls(camera, renderer.domElement);
    controls.enableDamping = true;

    // 2. Post-Processing Bloom
    const composer = new THREE.EffectComposer(renderer);
    composer.addPass(new THREE.RenderPass(scene, camera));
    const bloomPass = new THREE.UnrealBloomPass(
      new THREE.Vector2(window.innerWidth, window.innerHeight),
      1.8, 0.5, 0.1
    );
    composer.addPass(bloomPass);

    // 3. Add Particles
    const PARTICLE_COUNT = 3000;
    const geo = new THREE.BufferGeometry();
    const pos = new Float32Array(PARTICLE_COUNT * 3);
    for (let i = 0; i < PARTICLE_COUNT; i++) {
      pos[i * 3]     = (Math.random() - 0.5) * 30;
      pos[i * 3 + 1] = Math.random() * 20;
      pos[i * 3 + 2] = (Math.random() - 0.5) * 30;
    }
    geo.setAttribute('position', new THREE.BufferAttribute(pos, 3));

    const mat = new THREE.PointsMaterial({
      size: 0.15,
      color: 0x00ffff,
      transparent: true,
      opacity: 0.8,
      blending: THREE.AdditiveBlending
    });
    const particles = new THREE.Points(geo, mat);
    scene.add(particles);

    // 4. Animation Loop
    const clock = new THREE.Clock();
    function animate() {
      requestAnimationFrame(animate);
      const time = clock.getElapsedTime();

      // Move particles
      const positions = particles.geometry.attributes.position.array;
      for (let i = 0; i < PARTICLE_COUNT; i++) {
        positions[i * 3 + 1] -= 0.02; // fall
        if (positions[i * 3 + 1] < 0) positions[i * 3 + 1] = 20; // reset
      }
      particles.geometry.attributes.position.needsUpdate = true;

      controls.update();
      composer.render();
    }
    animate();

    // 5. Window Resize Handler
    window.addEventListener('resize', () => {
      camera.aspect = window.innerWidth / window.innerHeight;
      camera.updateProjectionMatrix();
      renderer.setSize(window.innerWidth, window.innerHeight);
      composer.setSize(window.innerWidth, window.innerHeight);
    });
  </script>
</body>
</html>
```

## ⚡ Performance Optimization & Best Practices

1. **Use `Float32Array` & `BufferGeometry`**: Always use typed arrays for thousands of vertices. Standard JavaScript arrays (`[]`) are too slow for per-frame 3D updates.
2. **Flag `needsUpdate = true` Only When Needed**: Only set `attributes.position.needsUpdate = true` when you actually modify vertex positions in JavaScript during a frame.
3. **Limit Pixel Ratio**: Always cap `renderer.setPixelRatio(Math.min(window.devicePixelRatio, 2))`. Rendering at native 4K on high-DPI laptop screens destroys frame rate.
4. **Use Additive Blending for Glow**: Combine `transparent: true` + `blending: THREE.AdditiveBlending` on points to make particles glow naturally when overlapping without heavy geometry.
5. **Clamp Delta Time**: When updating physics or positions in `animate()`, always clamp delta time (e.g. `Math.min(delta, 0.1)`) so particles don't jump across the screen if the user switches browser tabs.
